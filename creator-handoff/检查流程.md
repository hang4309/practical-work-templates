# 接收一份短视频交付

1. 先看交付说明：确认要的是哪一版、有字还是无字、有声还是无声。本示例是36秒有字无声版。
2. 实际播放主视频，核对开头、结尾和每处改动；需要声音的项目戴耳机核对。文件存在不能替代播放。
3. 对照timeline.md检查画面顺序与字幕意思。字幕版本必须与主片绑定；主片替换后即使名字不变，也重新检查。
4. 看素材记录及待办，找实际负责人补缺件。本包的程序不判授权或客户批准。
5. 将反馈写成“版本+时码+改前+改后+依据”。收到新一版时保留旧版，重新列清单，避免在聊天里混用“最终版”。

有Python时，可在解压目录运行：

```
python check_delivery.py example/manifest.json
```

退出码0表示清单内文件的路径、哈希及受支持的SRT约束一致；1表示需处理，2表示输入不适用或无法读取。结果只写到终端，不改素材。需要保存报告可重定向到清单目录之外的新文件。

这次额外检查会挡住：清单文件缺失、哈希变化、字幕重叠/倒序/越过声明片长、字幕绑定旧画面版本、路径越出目录。它只支持严格UTF-8 SRT：从1连续编号、HH:MM:SS,mmm时间行、每条非空文字；不支持样式参数、VTT、ASS或重叠说话者轨道。上限200个条目、SRT 2MiB、总文件2GiB。

它不会读取目录里所有未列出的文件，不读取视频内容，不推算真实片长，不判断翻译、朗读同步、版权或客户签收。对新项目先正确填写清单，清单自身是否完整需要交付负责人确认。不要把退出码0写成“所有内容验收通过”。
